# Step 1 - Constitution

**Input:** User constraints, repository instructions, existing configuration and constitution.
**Output:** Reused or updated `.specify/memory/constitution.md`.
**Completion:** Relevant shared constraints are available without inventing governance.
**Gate:** Use [Modes and Gates](../SKILL.md#modes-and-gates).

Read existing instructions and configuration first. Reuse a valid constitution across
Features. If one is needed, adapt the [template](../templates/constitution-template.md)
to capture only project-specific constraints and links to their authoritative sources.

Include relevant architecture boundaries, verification commands, supported environments,
and data/access requirements. Distinguish explicit requirements, observed conventions,
and assumptions. Preserve known stack constraints here; Step 5 owns new design choices.

Do not ask a generic six-topic questionnaire or invent coverage percentages, SLAs,
compliance claims, approval limits, or architecture layers to fill the template.
Resolve ordinary gaps from the repository. Ask only when a consequential missing fact
cannot be inferred under the shared decision policy.
